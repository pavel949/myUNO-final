open→ acknowledged→ in_progress⇄ waiting_reporter→ resolved→ closed

Naming conventions

Pick a convention once and the codebase reads itself.

Routes

lowercase, plural nouns, no verbs — /statements/[id], never /viewStatement

snake_case, past-tense where it is a state reached — checked_in, signed_off. Never rendered raw

domain.thing_unit — the unit is in the name, so nobody guesses minutes or hours

Stored UTC, displayed in Asia/Bangkok, formatted per locale — never an ISO string on screen

Where a thing belongs

The question that causes the most duplication, answered once.

A number the user sees

Computed server-side, always. Prices, totals, fees, SLA deadlines and countdowns are displayed, never derived in the browser — otherwise two clients disagree.

A rule that changes by project

A ConfigParameter with an override, not a branch in the code. If someone would ask "can we do it differently at Kata?", it is config.

A string a person reads

A content key. No literal copy in a component — that is what makes RU and TH a translation pass rather than a rebuild.

A status

An enum plus one mapping to label and colour, in one file. A second mapping anywhere is the bug.

Anything consequential

A human approval and an audit entry. Money moving, a role granted, a unit going live, a passport opened — never automatic, always attributable.

Nine rules

If a change breaks one of these, it needs an argument, not a shrug. Put them in the pull-request template.

1 · One identity

A person is one party ID across every journey. Never a second profile because the role changed.

2 · Roles are scoped

Always against a unit, project or organization. There is no global "owner".

3 · The menu is derived

Header and /app read the same resolver, so they cannot drift.

4 · Satang, divided once

Integers in the database, one formatter at the boundary.

5 · Figures trace

Any money shown to an owner opens to the rows behind it, or it should not be shown.

6 · Records are append-only

Ledger and statements are never edited. A correction is a new entry that supersedes.

7 · Never a blank screen

Empty, loading and error ship together, with copy written for that surface.

8 · Say what happens next

Every confirmation states the consequence in numbers before the person commits.

9 · Absent, not zero

Unknown shows nothing. A unit nobody reviewed has no rating, not a zero.
