# ROADMAP.md — Canonical Delivery Sequence

## Phase 0 — Baseline and safety
Current HEAD/open-PR reconciliation, schema/routes/runtime map, backup/restore proof, migration-hook risk, current public/mobile screenshots and current data ownership matrix. **Exit:** current system recoverable and facts separated from target state.

## Phase 1 — Critical correctness
Remove unsafe automatic migration-history repair from build/install; complete service-order lifecycle; align commission/remittance snapshots; correct settlement period/eligibility; harden fulfillment/cancel/dispute concurrency; add standalone-commerce scope foundation. **Exit:** current order-to-money path demonstrably consistent.

## Phase 2 — Shared contracts
OperatingScope authority, organization membership, ExternalSystem/Mapping, BusinessEvent, pricing canonicalization, physical capacity, offering terms versions and environment identity. **Exit:** authority, money, pricing and integration boundaries unambiguous.

## Phase 3 — Team and CRM
CRM Today/inbox/next actions, metric fixes, staff lifecycle, role workspaces and task/readiness baseline. **Exit:** team can run daily work without database/manual shadow systems.

## Phase 4 — Supply onboarding
Six-stage onboarding, owner/partner invite, existing-development reuse, import/dry-run, capability readiness, service/team/settlement config. **Exit:** normal new unit/property enters without developer.

## Phase 5 — Marketplace completion
Standalone customer, property service config, quote, reschedule, alternatives, provider workspace, settlement, products/rentals only when real supply is ready. **Exit:** discovery → order → fulfillment → exception → settlement is complete.

## Phase 6 — Public and role UX
Homepage, Explore/Stays, property pages/collections, services, My myUNO, guest trip, owner/partner acquisition, localization/mobile/accessibility. **Exit:** target experience coherent and practical.

## Phase 7 — Layantara federation
Mappings, event ingest/replay, identity reconciliation, portfolio projections, health and limited commands only where authority requires. **Exit:** central visibility without duplicated operational truth.

## Phase 8 — Distribution and expansion
ARI, partner feeds, packages/recurring, broader marketplace categories and standards analytics. **Exit:** each capability has independent readiness evidence.

## Major bottlenecks
1. Migration safety.
2. Financial/order state correctness.
3. Identity/scoped-CRM privacy.
4. Authority ambiguity.
5. Physical capacity duplication.
6. Marketplace cold start/fake breadth.
7. Multi-property configuration complexity.
8. Integration lag/authority confusion.
9. AI implementation drift.
10. OTA/channel overbooking.

## Scale target
Normal onboarding is configuration + data + verification, not new engineering. Track median onboarding hours, engineering interventions, data-quality failures, config reuse and time to live.
